# Harbor-format RL recipes converge on step-wise GRPO, but nobody has published the LUMI variant

**Bottom line.** Between September 2025 and September 2026 the public record on RL for terminal agents settled on one shape: an unmodified agent harness (Terminus-2, mini-SWE-agent, bash, OpenHands) talks to an OpenAI-compatible endpoint that captures token IDs and log-probs; environment and reward come from Harbor/Terminal-Bench-style task directories (instruction + Dockerfile + tests); the trainer runs a critic-free, group-baseline policy gradient (GRPO/RLOO/DPPO variants) with no KL, no entropy bonus, token-level loss, masked or zero-reward truncated episodes, and bounded-staleness asynchrony; rollouts execute in a separate fleet of containers or microVMs at 300–1,000+ concurrency. The single most relevant artifact for this reader is SkyRL's official Harbor integration (Feb 2026), which ships a Terminus-2 step-wise GRPO recipe on the FSDP backend with concrete defaults (group 8, batch 32, LR 1e-6, 32 turns, 32K context, 1,200 s agent timeout, 512 concurrent trials) [reported] ([run_codecontest.sh](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/run_codecontest.sh)). The single largest gap is that no one has published an end-to-end agentic RL run on AMD MI250X with Apptainer sandboxes; the closest public work is OpenEuroLLM's oellm-rlvr control plane on LUMI, which wires SkyRL + Harbor + Terminus-2 JSON to Apptainer overlay sandboxes but reports no training results [reported] ([oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr)). The recipe in Section 5 combines the SkyRL defaults, TMax's difficulty/group-size findings, NVIDIA's Apptainer-per-rollout pattern and the documented Harbor-on-Apptainer bugs into a concrete plan for a ~30B dense checkpoint at ~1,000 parallel trials.

## 1. Executive summary

- **Consensus recipe.** Every disclosed 2026 terminal/SWE RL pipeline (SkyRL-Harbor, prime-rl/verifiers, rLLM, NeMo Gym, TMax/open-instruct, Kimi K2.5, GLM-5, MiniMax Forge) runs an unmodified external harness against an OpenAI-compatible gateway that records token IDs/log-probs, takes reward from the task's own verifier, and uses a critic-free group-baseline policy gradient with no KL and no entropy loss [reported] ([SkyRL Harbor example](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/README.md), [verifiers v1](https://www.primeintellect.ai/blog/verifiers-v1), [rLLM](https://github.com/rllm-org/rllm), [DeepSWE](https://www.together.ai/blog/deepswe)).
- **Harbor is now the shared task contract.** SkyRL (official, Feb 2026), TRL (`trl.experimental.harbor`), prime-rl/verifiers (Harbor tasksets incl. TB2), NeMo Gym (Harbor Agent + `terminus_judge`), rLLM (`examples/harbor_swe`) and OpenEuroLLM (SkyRL+Harbor+Terminus-2 on LUMI) all consume Harbor task directories for training, not only eval [reported] ([SkyRL #866](https://github.com/NovaSky-AI/SkyRL/issues/866), [TRL docs](https://huggingface.co/docs/trl/harbor), [Prime blog](https://www.primeintellect.ai/blog/scaling-agentic-rl), [NeMo Gym #2045](https://github.com/NVIDIA-NeMo/Gym/issues/2045), [oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr)).
- **Best open 1B–32B numbers on TB2.0/2.1 come from data, not RL alone.** SFT-only Nemotron-Terminal-32B 27.4% and OpenThinker-Agent-32B 26.2% on TB2.0; RL-only Tmax-27B 44.9% and Tmax-9B 28.8% on TB2.1; Nemotron-Cascade-2-30B-A3B 40.5% TB2.0 after SFT+cascade RL [reported] ([NVIDIA 2602.21193](https://arxiv.org/abs/2602.21193), [OT-Agent](https://arxiv.org/pdf/2606.24855), [TMax](https://arxiv.org/html/2606.23321v1), [Cascade 2](https://arxiv.org/html/2603.19220v2)).
- **Biggest disagreement: SFT warm-start.** OpenThoughts-Agent finds "RL on top of moderately strong SFT outperforms other strategies"; TMax finds existing SFT mixtures *degraded* Qwen 3.5 and trains with no SFT; Klear-AgentForge reports reasoning+agentic SFT caused collapse. No public work does sandboxed agentic RL from a raw base model [reported/inferred] ([OT-Agent](https://arxiv.org/pdf/2606.24855), [TMax](https://arxiv.org/html/2606.23321v1), [Klear](https://arxiv.org/html/2511.05951v1)).
- **Second disagreement: group size and context.** Group 8 (SkyRL, SkyRL-Agent, DeepSWE, CWM) vs 16 (INTELLECT-3, Nemotron, Prime configs) vs 32 (TMax: "32 vs 8 improved stability"; GLM-5 reasoning). Context 32K (SkyRL, NVIDIA SFT ablation: 32K > 64K) vs 64K–131K (DeepSWE ≤2% gain beyond 32K; CWM/Prime 131K) [reported] (links in Section 2).
- **Difficulty beats volume for RL.** Tmax-15k (pass@1 42%) trains stronger models than Endless Terminals (pass@1 92%); Cascade 2 drops 100%-pass tasks and 90% of 0%-pass tasks; SETA's partial-credit reward raised tasks with reward variance from 49% to 86% [reported] ([TMax](https://arxiv.org/html/2606.23321v1), [Cascade 2](https://arxiv.org/html/2603.19220v2), [SETA](https://arxiv.org/html/2607.10891)).
- **Anti-reward-hacking is a live loop, not a filter.** Qwen agents learned `git remote add`/`curl` to fetch ground-truth commits after remotes were stripped; Prime withholds all grading material until scoring; Anthropic removed "around half" of computer-use environments for hack surfaces [reported] ([Qwen3-Coder-Next](https://arxiv.org/abs/2603.00729), [Prime](https://www.primeintellect.ai/blog/scaling-agentic-rl), [Fable 5.1 card via Zvi](https://thezvi.wordpress.com/2026/09/04/claude-fable-5-1-and-mythos-5-1-the-system-card/)).
- **Closed labs disclose benchmark numbers and hack taxonomies, not recipes.** OpenAI, Anthropic, Google, xAI, Mistral: environment counts, sandbox tech at training time, algorithm and turns are all not disclosed; Meta (CWM, SSR) is the only Western lab with a full numeric 32B recipe [reported] ([CWM](https://arxiv.org/html/2510.02387v1), [SSR](https://arxiv.org/html/2512.18552v1)).
- **HPC/Apptainer is thinly documented but real.** Harbor ships a native Singularity backend with known bugs (PATH shadowing hit 46/88 TB-2.1 tasks; `tag@digest` refs rejected; FUSE `user_allow_other` missing); NVIDIA runs Super's SWE-RL as one Apptainer container per rollout under Slurm; NeMo Gym ships Apptainer and enroot providers; TMax uses Podman/Apptainer [reported] ([harbor #3126](https://github.com/harbor-framework/harbor/issues/3126), [harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc), [Super report](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf)).
- **ROCm/MI250X is the reader's biggest risk.** SkyRL's AMD PR was closed unmerged on 2026-09-17; verl officially lists only MI300X/MI350X; but verl 0.8.0 + vLLM + Megatron GRPO demonstrably scales 1→16 LUMI-G nodes and prime-rl ran Poro 2 RL on LUMI MI250X [reported] ([SkyRL PR #2225](https://github.com/NovaSky-AI/SkyRL/pull/2225), [verl AMD](https://verl.readthedocs.io/en/latest/amd_tutorial/amd_quick_start.html), [LUMI AIF](https://lumi-ai-factory.eu/articles/scaling-reinforcement-learning/), [ROCm playbook](https://rocm.blogs.amd.com/artificial-intelligence/rl-training-playbook/README.html)).

## 3. Harbor section

### 3.1 Every public use of Harbor / Terminal-Bench-format tasks for training

**OpenThoughts-Agent (Laude Institute).** The most complete Harbor-native training pipeline. Teacher trajectories were generated by GLM-4.7-AWQ "in terminus-2 harness within Daytona sandboxes" at 32,768 context, with Harbor used for "environment/benchmark/harness management"; RL used an "Extended SkyRL (RLOO algorithm)" fork with async rollouts and binary test rewards on 5K `pymethods2test` tasks, on 24×A100-80GB for ~46 hours [reported] ([arXiv PDF](https://arxiv.org/pdf/2606.24855)). The repo ships Harbor YAML templates under `hpc/harbor_yaml/`, HPC configs for TACC, JURECA and JUWELS, and names Daytona primary with Docker, Modal, e2b and Podman alternatives [reported] ([GitHub](https://github.com/open-thoughts/OpenThoughts-Agent)). Its v1 RL dataset defines a task as "a triplet of an instruction in the form of a markdown file, an environment defined by a DockerFile, and a verifier in the form of pytests" with a 3-stage filter (flaky/slow verifiers, slow builds, optional GPT-5-Codex difficulty filter) [reported] ([HF v1-RL](https://huggingface.co/datasets/open-thoughts/OpenThoughts-Agent-v1-RL)). Training-side ablations: task source has the largest spread (30 pp on SWE-Bench-Verified-100), filtering traces under 5 turns gave the largest trajectory-filter gain, and "RL on top of moderately strong SFT outperforms other strategies" (8B: 24.3→35.7 SWE-V-100) [reported] ([arXiv PDF](https://arxiv.org/pdf/2606.24855)).

**SkyRL official integration (NovaSky).** Issue #866 tracked upstreaming from the `mlfoundations/SkyRL` fork; it closed 2026-02-24 with an async PPO trainer, custom vLLM chat template, `served_model_name`, Harbor `TrialConfig` pass-through, trials/sec rate limiting and concurrency control, and Modal support (#1022); still open: fully async/step-wise training (#1206), agents beyond Terminus-2 (#1184), integration CI (#1207) [reported] ([SkyRL #866](https://github.com/NovaSky-AI/SkyRL/issues/866)). The example directory contains `harbor_generator.py` ("bridges SkyRL <-> Harbor"), `HarborTaskDataset` (loads task directory paths), `prepare_harbor_dataset.py` (downloads from HF), and `harbor_trial_config/default.yaml` [reported] ([README](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/README.md)). Defaults: agent `terminus-2`, `override_timeout_sec: 1200`, `max_turns: 32`, `enable_summarize: false` (required for step-wise training), `collect_rollout_details: true`, temperature 1.0, `max_input_tokens`/`max_output_tokens` 32768, LLM request timeout 900 s, `max_retries: 0`, environment `daytona` (options daytona/docker/e2b/modal/runloop/gke), `override_cpus: 1`, `override_memory_mb: 1024`, `override_storage_mb: 1024` [reported] ([default.yaml](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/harbor_trial_config/default.yaml)). Failure semantics in the generator: stop reasons `complete | context_length | agent_timeout | error`; "Retries on unknown errors; context length errors train with reward=0; agent timeouts mask the trajectory"; reward is `float(results.verifier_result.rewards["reward"])` recorded on the last turn with zeros elsewhere [reported] ([harbor_generator.py](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/harbor_generator.py)). Third-party layers on top: `fleet-ai/harbor-train` ("clean upstream SkyRL + SkyPilot layer") and MarinSkyRL (issue #538: "Terminus-2 rollouts fail on /tokenize against the SkyRL HTTP endpoint") [reported] ([harbor-train](https://github.com/fleet-ai/harbor-train), [MarinSkyRL #538](https://github.com/marin-community/MarinSkyRL/issues/538)). Mercor's September 2026 write-up is the largest disclosed SkyRL+Harbor run: 550 concurrent rollouts for Qwen3.6-35B-A3B and 300 for Qwen3.5-397B-A17B on Modal, inference:train node ratio 12:4 and 12:8, vLLM + Megatron, fully async with in-flight weight updates [reported] ([Mercor](https://www.mercor.com/blog/training-frontier-knowledge-work-agents-a-397b-rl-training-guide-with-skyrl/)).

**NVIDIA.** Nemotron-Terminal's data pipeline (Terminal-Task-Gen) runs Terminus 2 in "Harbor framework extended with Singularity support for HPC clusters; Daytona for reliable isolated cloud execution", using 9 pre-built domain images instead of per-task Dockerfiles [reported] ([arXiv](https://arxiv.org/html/2602.21193v1)). The RL dataset Nemotron-RL-Agentic-Terminal-Pivot-v1 was "Generated using Terminus-2 agent (v2.0.0) in Harbor execution harness" (teacher GLM-5.1), keeping at most 5 verifier-passing trajectories per task, and routes to NeMo Gym's `terminus_judge` resource server for RLVR [reported] ([HF](https://huggingface.co/datasets/nvidia/Nemotron-RL-Agentic-Terminal-Pivot-v1)). Nemotron-Cascade 2's terminal RL used the same 490K Terminal-Task-Gen tasks in isolated Docker environments with the Terminus 2 scaffold [reported] ([arXiv](https://arxiv.org/html/2603.19220v2)). NeMo Gym issue #2045 "Validate and document Harbor task and agent interoperability" names "Terminus as the reference integration" and targets "token metadata required for multi-turn RL training" [reported] ([#2045](https://github.com/NVIDIA-NeMo/Gym/issues/2045)); the NeMo Gym README lists a "Harbor Agent for container-backed envs" and "Anyterminal Agent (Terminal Bench)" resource servers [reported] ([README](https://github.com/NVIDIA-NeMo/Gym/blob/main/README.md)).

**Prime Intellect.** verifiers v1 (July 2026) ports Terminal Bench 2 by setting "the dataset to the same name as registered in the Harbor registry" with "No need for a reward function, as it will get inherited from the Harbor dataset"; Terminus 2 is one of four built-in harnesses [reported] ([verifiers v1](https://www.primeintellect.ai/blog/verifiers-v1)). The scaling blog states "Terminal-Bench 2 wraps it through the same Harbor taskset, so the eval suite and the training corpora share one task format and one scoring contract", covering ~28,600 terminal tasks (TMax 14,600; Terminal-Lego ~13,800; OpenThoughts-TBLite 100; TB2 89) [reported] ([Prime blog](https://www.primeintellect.ai/blog/scaling-agentic-rl)). prime-rl's GLM-4.5-Air `terminal.toml` trains on `tmax` and evaluates `terminal-bench-2` at group 4 with `timeout.rollout = 3600` [reported] ([terminal.toml](https://github.com/PrimeIntellect-ai/prime-rl/blob/main/examples/advanced/glm-4.5-air/terminal.toml)). Harbor plumbing PRs: configurable artifact transfer budgets (#2567) and MCP declarations wired into task toolsets (#2546) [reported] ([#2567](https://github.com/PrimeIntellect-ai/verifiers/pull/2567), [#2546](https://github.com/PrimeIntellect-ai/verifiers/pull/2546)).

**TRL (Hugging Face).** `trl.experimental.harbor` gives `GRPOTrainer` an `environment_factory`; `HarborSpec(dataset, agent="bash", num_tasks=64)` yields a `train_dataset` and `HarborEnv` whose `reset(task_dir)` provisions the sandbox and whose `env.reward` runs `tests/` once; backends `docker` (default) or `e2b` ("recommended for cluster training"); requires `vllm>=0.22.0`, `transformers>=5.2.0`; limits are sequential sandbox provisioning and one suite per spec [reported] ([TRL docs](https://huggingface.co/docs/trl/harbor)). [inferred] This is trainer-driven (TRL owns the loop; only `exec` crosses into the sandbox), unlike SkyRL/NeMo Gym where Terminus-2 runs inside Harbor against a served policy.

**rLLM (Agentica).** Docs reference a "Harbor SWE reproducer available in examples/harbor_swe" and list Terminal-Bench-RL (Terminal-Bench task directories → parquet, Docker per rollout) among projects [reported] ([rLLM docs](https://docs.rllm-project.com/projects/deep-swe), [terminal-bench-rl](https://github.com/Danau5tin/terminal-bench-rl)).

**OpenEuroLLM oellm-rlvr (LUMI).** "LUMI-first math and code RLVR rollout control plane with ROCm and CUDA profiles"; Slurm submission; multi-node Ray with learner/rollout topology validation; vLLM with native weight transfer; TMAX/open-instruct backend for GRPO/DPPO, verl adapter for on-policy distillation; agentic rollouts via "SkyRL + Harbor framework with Terminus-2 JSON interface"; "Generated code runs exclusively in Apptainer sandboxes using task-specific images… Verification uses Apptainer overlays with read-only base images, bounded timeouts, and isolated workspace directories" [reported] ([oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr)). OpenEuroLLM Taskboard #386 "Bring up and validate the agentic RL stack on LUMI" is In Progress and plans to evaluate "Nemotron Gym components" [reported] ([#386](https://github.com/OpenEuroLLM/Taskboard/issues/386)).

**Others.** Snowflake Arctic-Platform PR #66 "harbor: Cortex training backend as a Harbor plugin (draft)" [reported, not fetched] ([PR](https://github.com/Snowflake-AI-Research/Arctic-Platform/pull/66)); abundant-ai/harbor-trainer exists (DeepWiki only) ([DeepWiki](https://deepwiki.com/abundant-ai/harbor-trainer)); Anthropic evaluates TB2.0 "using the Terminus-2 harness, in the Harbor scaffold" but discloses no training use [reported] ([Opus 4.5 card](https://www-cdn.anthropic.com/bf10f64990cfda0ba858290be7b8cc6317685f47/Claude%20Opus%204.5%20System%20Card.pdf)). No primary-source evidence of Harbor integration in verl, slime, AReaL, ROLL or OpenRLHF was found [reported as absent].

### 3.4 Harbor's Singularity/Apptainer backend and known HPC issues

Harbor's docs list `singularity` as a local runtime alongside `docker`, `podman`, `apple-container`, plus ~20 remote providers; selection is via `-e/--env`; `-n/--n-concurrent` defaults to 4; `--cpus`/`--memory` modes and `--ek/--environment-kwarg` pass backend kwargs [reported] ([sandbox docs](https://docs.harborframework.com/core-concepts/sandboxes/pre-integrated-sandboxes.md)). The llms.txt index says the sandbox page "Covers Docker, Daytona, Modal, E2B, Runloop, Apptainer, Slurm", but the fetched page contains no Apptainer/Slurm limitations [reported] ([llms.txt](https://docs.harborframework.com/llms.txt)).

Implementation: `harbor/environments/singularity/server.py` is an in-container HTTP command server bootstrapped inside an Apptainer instance; the bootstrap installs Debian `python3-minimal` if the image lacks it and prepends `/usr/bin:/usr/local/bin:` to PATH, which shadows `/usr/local/bin/python3` in `python:*-slim` images so `python3` lacks image packages. Of 88 Terminal-Bench 2.1 tasks, 46 have Python only in `/usr/local`; oracle passes rose 37→42 after reordering PATH. This was discovered "verifying Terminal-Bench 4.0 on an unprivileged Apptainer 1.3.3 cluster with Harbor 0.22.0" [reported] ([harbor #3126](https://github.com/harbor-framework/harbor/issues/3126)). Fix PR #3146 (2026-09-16, open) preserves inherited PATH and appends bootstrap dirs; test failures 23→11 [reported] ([PR #3146](https://github.com/harbor-framework/harbor/pull/3146)). PR #1722 made `singularity_server_start_timeout` configurable (default 300 s; `--ek singularity_server_start_timeout=600`), replaced a port probe that "could be satisfied by unrelated services" with a nonce-echoing `/health` and wall-clock deadline; `environment.build_timeout_sec` still bounds conversion+staging+startup [reported] ([PR #1722](https://github.com/harbor-framework/harbor/pull/1722)). harbor-datasets issue #254 reports a TMax-15K-Harbor task "contains an unconverted Singularity runtime hook" [reported] ([#254](https://github.com/harbor-framework/harbor-datasets/issues/254)). A Terminus-2 hazard independent of backend: the agent's `rm -rf /tmp/*` deletes the tmux socket and kills the trial (issue #3294) [reported] ([#3294](https://github.com/harbor-framework/harbor/issues/3294)).

The community fork harbor-singularity-hpc (Sept 2026) targets clusters where `/etc/fuse.conf` lacks `user_allow_other`, so `--writable-tmpfs` fails; it extracts images to directories and runs `--fakeroot --writable <dir>`, pre-creates bind-mount destinations, parses `Dockerfile FROM` to pull base images ("Harbor's Singularity backend does not build Dockerfiles"), caches images node-locally in `$PBS_LOCALDIR`/`$SLURM_TMPDIR`, throttles `singularity pull` against Docker Hub rate limits, and raises Harbor's default 600 s HTTP timeout to a floor of 86,400 s; tested on harbor 0.22.x [reported] ([harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc)). Its PR #3 fixes that Apptainer rejects Docker references carrying both a tag and a digest (`Docker references with both a tag and digest are currently not supported`), while Harbor pins images as `repo:tag@sha256:<digest>`, so all pulls failed; fix strips the tag [reported] ([PR #3](https://github.com/lintangsutawika/harbor-singularity-hpc/pull/3)). [inferred] Because the fork relies on `--fakeroot`, which LUMI disables, the reader must use plain `--writable` on a user-owned sandbox directory or `--writable-tmpfs` where the site permits (Section 5.7).

NeMo Gym's Apptainer provider is the reference pattern for instance-per-sandbox: `apptainer instance start --bind <staging>:<mount> … <image> <name>`, exec via `apptainer exec instance://<name> sh -c <cmd>`; images as local `.sif`, `docker://`, or bare Docker names; `--fakeroot` only when running as root; `--writable-tmpfs` via `extra_exec_args`; `--cpus`/`--memory` need cgroups; per-command timeout 180 s; instance start timeout 600 s; `ttl_s` unsupported; disk quotas unenforceable [reported] ([NeMo Gym Apptainer](https://docs.nvidia.com/nemo/gym/infrastructure/sandbox/apptainer/)). Its enroot provider (unprivileged, `.sqsh` cache, default asyncio semaphore 32) is an alternative where enroot exists [reported] ([enroot docs](https://docs.nvidia.com/nemo/gym/nemo-gym/nemo_gym/sandbox/providers/enroot/provider/)). No throughput numbers (trials/hour, instance-start seconds) for Harbor-on-Apptainer exist in any primary source [reported gap].

## 5. Recommendations for the reader's setup

Target: ~30B dense base/lightly-tuned checkpoint, terminus-2 on Harbor + SkyRL FSDP, LUMI (MI250X, ROCm, Slurm, Apptainer only), ≈10 datasets × ≈100 tasks, ≈1,000 parallel trials. Every number below names its source; where no source covers the reader's exact case, the line is marked [inferred].

### 5.1 Task mix and count (~1,000 tasks)

Take the 10 datasets from Section 3.2/4 that already are, or trivially become, Harbor task directories, and subsample ~100 each after a difficulty pass: Tmax-15k (hard, domain-balanced; pass@1 42% for Gemini-3-Flash vs 92% for Endless Terminals) [reported] ([TMax](https://arxiv.org/html/2606.23321v1)); Terminal-Lego-15k (task.toml preserved, prebuilt images) [reported] ([HF](https://huggingface.co/datasets/hamishivi/agent-task-terminal-lego-15k)); SETA-Env (sysadmin-heavy, no-op/oracle-tested) [reported] ([SETA](https://arxiv.org/html/2607.10891)); OpenThoughts-Agent-v1-RL (nl2bash) [reported] ([HF](https://huggingface.co/datasets/open-thoughts/OpenThoughts-Agent-v1-RL)); Nemotron Terminal-Pivot seed tasks if their images can be reconstructed [inferred]; open-thoughts/CodeContests (SkyRL quickstart) [reported] ([README](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/README.md)); and three SWE-bench-schema sets wrapped as Harbor tasks (SWE-smith, R2E-Gym, SWE-rebench-V2 for non-Python) [inferred]. Rationale for including SWE: OpenThoughts-Agent's best SFT sources by TB2.0 score were StackExchange SuperUser (10.86%) and Tezos (9.36%) while SWE-smith gave the best SWE-V-100 (32.33%); mixing top-4 to top-8 sources beat any single source [reported] ([OT-Agent](https://arxiv.org/pdf/2606.24855)). Hold out TB2.0/2.1 entirely and use OpenThoughts-TB-dev (100) or harbor-mix (100) as dev sets [reported] ([README](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/README.md), [harbor-mix](https://huggingface.co/datasets/harborframework/harbor-mix)).

Difficulty filtering: estimate pass rate with 8–16 rollouts of a small model (INTELLECT-3 used Qwen3-4B over 8–16 generations) [reported] ([INTELLECT-3](https://arxiv.org/html/2512.16144v1)); remove tasks at 100% pass and 90% of tasks at 0% (Cascade 2) [reported] ([Cascade 2](https://arxiv.org/html/2603.19220v2)); at train time drop zero-std groups (TMax "soft filtering"; SkyRL/prime-rl resample rejected groups) [reported] ([TMax](https://arxiv.org/html/2606.23321v1), [prime-rl algorithms](https://github.com/PrimeIntellect-ai/prime-rl/blob/main/docs/algorithms.md)). Optionally run a SETA-Evol-style band (>50% pass → harder; 0% → easier) [reported] ([SETA](https://arxiv.org/html/2607.10891)). Flakiness: run each verifier 10× on the oracle and on a no-op agent before admitting a task (Prime's "10× retries", no-op and gold-patch validation) [reported] ([Prime](https://www.primeintellect.ai/blog/scaling-agentic-rl)); OpenThoughts-v1-RL's filter also removed slow container builds [reported] ([HF](https://huggingface.co/datasets/open-thoughts/OpenThoughts-Agent-v1-RL)). Decontaminate instructions against TB2.0/2.1 with 13–14-gram overlap (NVIDIA 14-gram; TMax 13-gram) and filter the Big-Bench canary string [reported] ([NVIDIA](https://arxiv.org/html/2602.21193v1), [TMax](https://arxiv.org/html/2606.23321v1), [TB paper](https://arxiv.org/pdf/2601.11868)).

Apptainer-specific exclusions [inferred from Apptainer semantics]: drop tasks whose Dockerfile or verifier needs root at runtime (`apt install` during the trial, privileged ports, `USER` switching — Apptainer ignores `USER`), nested containers (Docker-in-Docker), or FUSE mounts [reported basis] ([Apptainer docker & OCI](https://apptainer.org/docs/user/latest/docker_and_oci.html)). Expect this to remove a meaningful fraction of SysAdmin-category tasks; measure it on the oracle run (harbor-singularity-hpc saw 11 residual failures on TB-2.1 after the PATH fix) [reported] ([PR #3146](https://github.com/harbor-framework/harbor/pull/3146)).

### 5.2 SFT warm-start for a base model

The reader starts from a base checkpoint. No public work does sandboxed agentic RL from a raw base; every lab cold-starts with SFT (Kimi K2/K2.5/K3, GLM-4.5/5, MiniMax M2, DeepSeek-V3.2, Qwen3-Coder-Next), and Nemotron-Cascade started from Qwen3-Base but SFT'd first [reported] ([K3](https://arxiv.org/abs/2607.24653), [GLM-5](https://arxiv.org/abs/2602.15763), [Cascade 1](https://arxiv.org/html/2512.13607v1)). The counter-evidence (TMax "no SFT") applies to Qwen 3.5 instruct-hybrid checkpoints, where "existing SFT mixtures" degraded the model, while TMax SFT helped Qwen3-8B [reported] ([TMax](https://arxiv.org/html/2606.23321v1)). Recommendation: a *light, format-matched* SFT so the base emits valid terminus-2 JSON and stays in-distribution for step-wise merging, then RL. Data: OpenThoughts-Agent-v1-SFT (15.2K, Apache-2.0, terminus-2, ≤32 turns) plus a subsample of Nemotron-Terminal-Corpus (366K, CC-BY-4.0, terminus-2 format) [reported] ([HF v1-SFT](https://huggingface.co/datasets/open-thoughts/OpenThoughts-Agent-v1-SFT), [HF corpus](https://huggingface.co/datasets/nvidia/Nemotron-Terminal-Corpus)). Keep failed trajectories (NVIDIA: no-filter 12.4 vs success-only 5.06 on TB2.0; TermiGen τ≥0% 31.3 vs τ=100% 25.0) but drop traces with fewer than 5 turns (OT-Agent) [reported] ([NVIDIA](https://arxiv.org/html/2602.21193v1), [TermiGen](https://arxiv.org/html/2602.07274v1), [OT-Agent](https://arxiv.org/pdf/2606.24855)). Hyperparameters from the two 32B recipes: NVIDIA LR 2e-5, 2 epochs, seq 32,768, GBS 128 (32B on 128 GPUs) vs OT-Agent LR 4e-5, 7 epochs, batch 96 [reported] ([NVIDIA](https://arxiv.org/html/2602.21193v1), [OT-Agent](https://arxiv.org/pdf/2606.24855)). Use 32K sequence length: NVIDIA's 8B ablation found 32K (13.0) > 64K+YaRN (11.9) > 64K (10.3) [reported] ([NVIDIA](https://arxiv.org/html/2602.21193v1)). [inferred] Aim for 10–20K traces, 2 epochs, LR 2e-5: enough for format, not enough to overfit the teacher's scaffold habits; OT-Agent's "moderately strong SFT" is the target, not a maximal SFT. Avoid mixing long-CoT reasoning SFT with agentic SFT (Klear collapse) [reported] ([Klear](https://arxiv.org/html/2511.05951v1)).

### 5.3 Algorithm and loss

Start from the SkyRL Harbor example verbatim: `advantage_estimator=grpo`, `loss_reduction=token_mean` ("with step-wise training, we have to use token_mean to be prefix-merge-invariant"), `grpo_norm_by_std=false`, `use_kl_loss=false`, `apply_overlong_filtering=true`, TIS off-policy correction `tis_ratio_type=token`, `token_tis_ratio_clip_high=2.0`, `step_wise_trajectories=true`, `merge_stepwise_output=true`, custom chat template `qwen3_acc_thinking.jinja2` that keeps thinking tokens across steps [reported] ([run_codecontest.sh](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/run_codecontest.sh)). This matches the cross-lab consensus of no KL and no entropy loss (DeepSWE GRPO++, SkyRL-Agent, Cascade 2, GLM-4.5) [reported] ([DeepSWE](https://www.together.ai/blog/deepswe), [SkyRL-Agent](https://arxiv.org/html/2511.16108v1), [Cascade 2](https://arxiv.org/html/2603.19220v2), [GLM-4.5](https://arxiv.org/abs/2508.06471)). Alternatives to A/B if GRPO is unstable: leave-one-out/RLOO (SkyRL supports RLOO; OT-Agent and SkyRL-Agent used it) [reported] ([skyrl-train README](https://github.com/NovaSky-AI/SkyRL/blob/main/skyrl-train/README.md), [OT-Agent](https://arxiv.org/pdf/2606.24855)); divergence-based token masking (TMax DPPO; GLM-5 token-level IS masking; K2.5 log-ratio masking "essential for maintaining training stability in complex domains requiring long-horizon, multi-step tool-use") [reported] ([TMax](https://arxiv.org/html/2606.23321v1), [GLM-5](https://arxiv.org/abs/2602.15763), [K2.5](https://arxiv.org/abs/2602.02276)). Use an FP32 LM head if the policy is a Qwen 3.5-family checkpoint (TMax) [reported] ([TMax](https://arxiv.org/html/2606.23321v1)). Loss masking: tool observations are masked by default in every framework (prime-rl documents it explicitly; SkyRL step-wise records only model tokens) [reported] ([prime-rl algorithms](https://github.com/PrimeIntellect-ai/prime-rl/blob/main/docs/algorithms.md), [harbor_generator.py](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/harbor_generator.py)); agent timeouts are loss-masked, context-length overflows get reward 0 (SkyRL), and sandbox/infra failures are excluded from the batch (INTELLECT-3 masks sandbox failures; GLM-5 drops "environment collapse" samples) [reported] ([INTELLECT-3](https://arxiv.org/html/2512.16144v1), [GLM-5](https://arxiv.org/abs/2602.15763)).

### 5.5 Reward design and anti-hacking

Reward = Harbor verifier output from `/logs/verifier/reward.txt|json` on the last turn [reported] ([configuration.md](https://docs.harborframework.com/core-concepts/tasks/configuration.md), [harbor_generator.py](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/harbor_generator.py)). Prefer graded verifiers where the dataset provides them (SETA's fraction-of-tests + 0.2 completion bonus raised variance-bearing tasks 49%→86%; NVIDIA uses weighted partial credit) but keep TB-style binary tasks binary [reported] ([SETA](https://arxiv.org/html/2607.10891), [NVIDIA](https://arxiv.org/html/2602.21193v1)). Add mild cost shaping only after the first stable run: Prime's linear penalty (input tokens weight 0.1, turns weight 0.1, output tokens 0) and Qwen's unfinished-trajectory and invalid-tool-call token penalties [reported] ([terminal.toml](https://github.com/PrimeIntellect-ai/prime-rl/blob/main/examples/advanced/glm-4.5-air/terminal.toml), [Qwen3-Coder-Next](https://arxiv.org/abs/2603.00729)). Avoid LLM-judge blends at first (TB-RL's 65/35 judge blend never completed a run) [reported] ([terminal-bench-rl](https://github.com/Danau5tin/terminal-bench-rl)).

Anti-hacking checklist drawn from the sources: withhold test files and grading scripts from the container until scoring (Prime; R2E-Gym originally shipped tests at `/r2e_tests`) [reported] ([Prime](https://www.primeintellect.ai/blog/scaling-agentic-rl)); strip `.git` history, remotes, branches and tags (SWE-Lego, SSR, Qwen) [reported] ([SWE-Lego](https://arxiv.org/html/2601.01426v2), [SSR](https://arxiv.org/html/2512.18552v1), [Qwen3-Coder-Next](https://arxiv.org/abs/2603.00729)); set `network_mode = "no-network"` or an allowlist in task.toml for tasks that don't need the network, and if network is required, block tool calls that combine a repo URL with `git|curl|wget` (Qwen's heuristic, added after agents learned `git remote add`) [reported] ([configuration.md](https://docs.harborframework.com/core-concepts/tasks/configuration.md), [Qwen3-Coder-Next](https://arxiv.org/abs/2603.00729)); reset test files to originals before running the suite (SSR) [reported] ([SSR](https://arxiv.org/html/2512.18552v1)); grade final environment state, not self-reported completion (K3) [reported] ([K3](https://arxiv.org/abs/2607.24653)); grep trajectories for `sys.exit(0)`, `__eq__` overrides, `conftest.py` monkey-patches and pytest stubs (Anthropic/OpenAI hack taxonomies) [reported] ([Anthropic](https://arxiv.org/abs/2511.18397), [OpenAI](https://openai.com/index/chain-of-thought-monitoring/)). [inferred] On Apptainer the missing network namespace by default means `network_mode` may not be enforceable inside the container; enforce it at the Slurm node level (no-network partitions or egress proxy) and verify per task.

### 5.6 Context management and step-wise training

Keep `enable_summarize: false` so each trajectory is a single prefix-merge-invariant sequence; overlong episodes are filtered rather than compacted [reported] ([default.yaml](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/harbor_trial_config/default.yaml), [run_codecontest.sh](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/run_codecontest.sh)). Terminus-2 already truncates terminal output to 10,000 bytes and triggers a 3-subagent summarize/question/answer handoff when free tokens drop below 8,000; the subagent trajectories are logged separately with token IDs/logprobs [reported] ([terminus_2.py](https://github.com/harbor-framework/harbor/blob/main/src/harbor/agents/terminus_2/terminus_2.py)). If longer horizons are later needed, the published path is verifiers v1's DAG-branch traces, which make "training across compactions and subagents feasible", or prime-rl's `compaction.summarize_at_tokens = 98304` at 131K [reported] ([verifiers v1](https://www.primeintellect.ai/blog/verifiers-v1), [terminal.toml](https://github.com/PrimeIntellect-ai/prime-rl/blob/main/examples/advanced/glm-4.5-air/terminal.toml)); SkyRL's equivalent (#1206) is still open [reported] ([#866](https://github.com/NovaSky-AI/SkyRL/issues/866)). Use the JSON parser (Kimi K2.5 and Qwen report JSON > XML on TB2.0: 39.3 vs 34.8 for DeepSeek-V3.2; 36.2 vs 34.2 for Coder-Next) [reported] ([Qwen3-Coder-Next](https://arxiv.org/abs/2603.00729)). Watch the `rm -rf /tmp/*` tmux-socket hazard (#3294) [reported] ([#3294](https://github.com/harbor-framework/harbor/issues/3294)).

### 5.7 Rollout infrastructure on LUMI: Apptainer, Slurm, Lustre

**Topology.** Every disclosed large pipeline separates the sandbox fleet from GPU workers and talks over HTTP [inferred] (Kimi K2 "deploy heavy environments as dedicated services"; RollArt CPU K8s pools; NVIDIA Super "hundreds of concurrent" Apptainer sandboxes under Slurm) [reported] ([K2](https://arxiv.org/pdf/2507.20534), [RollArt](https://arxiv.org/html/2512.22560v1), [Super](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf)). Recommended layout [inferred]: a Slurm heterogeneous job or two co-scheduled jobs — GPU nodes for SkyRL trainer + vLLM engines, CPU nodes (LUMI-C) hosting Harbor's Singularity environments, with Harbor's `QueueOrchestrator` (retries/concurrency, PR #1074 rate limits) as the queue and the SkyRL `MAX_CONCURRENCY` cap as backpressure [reported basis] ([#866](https://github.com/NovaSky-AI/SkyRL/issues/866)). Inference:train GPU ratio ~3:1 (Mercor 12:4; Poro 2 on MI325X 1 trainer : 3 inference nodes; TMax 2 train : 6 inference; INTELLECT-3 16:44) [reported] ([Mercor](https://www.mercor.com/blog/training-frontier-knowledge-work-agents-a-397b-rl-training-guide-with-skyrl/), [ROCm playbook](https://rocm.blogs.amd.com/artificial-intelligence/rl-training-playbook/README.html), [TMax](https://arxiv.org/html/2606.23321v1), [INTELLECT-3](https://arxiv.org/html/2512.16144v1)). For 1,000 concurrent trials at 1–2 CPU each, that is ~8–16 LUMI-C nodes [inferred; LUMI-C core counts not in the notes].

**Images: the docker-archive route.** LUMI disables `sudo` and `fakeroot`, so `singularity build` from a definition file is impossible; approved routes are cotainr, build elsewhere and transfer, or unprivileged PRoot builds, and `singularity pull docker://…` works [reported] ([LUMI Singularity docs](https://docs.lumi-supercomputer.eu/software/containers/singularity/)). Harbor's Singularity backend does not build Dockerfiles [reported] ([harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc)), and Apptainer's own `dockerfile:` source needs a running BuildKit/Docker daemon [reported] ([Apptainer build](https://apptainer.org/docs/user/latest/build_a_container.html)). Therefore: build all ~1,000 task images on a Docker-capable machine (or pull prebuilt ones — Terminal-Lego-15k ships `hamishi740/…:<hash>`, Tmax per-domain images), `docker save` → `docker-archive:` → `apptainer build task.sif docker-archive://…` or a `--sandbox` directory, and stage to LUMI [reported basis] ([Apptainer docker & OCI](https://apptainer.org/docs/user/latest/docker_and_oci.html), [Terminal-Lego HF](https://huggingface.co/datasets/hamishivi/agent-task-terminal-lego-15k)). Set `task.toml [environment] docker_image` to the prebuilt reference so Harbor pulls rather than builds [reported] ([configuration.md](https://docs.harborframework.com/core-concepts/tasks/configuration.md)). Strip tags from `tag@digest` references or apply the harbor-singularity-hpc PR #3 patch [reported] ([PR #3](https://github.com/lintangsutawika/harbor-singularity-hpc/pull/3)). Throttle Docker Hub pulls (rate limits hit Prime at "a thousand concurrent rollouts"; the HPC fork adds bounded retry + process-wide throttling) [reported] ([Prime](https://www.primeintellect.ai/blog/scaling-agentic-rl), [harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc)).

**Writable layers without user namespaces.** Without setuid or userns, `--fakeroot` cannot run; fakeroot "mode 4" needs a sandbox directory and cannot install some packages [reported] ([Apptainer fakeroot](https://apptainer.org/docs/user/latest/fakeroot.html), [user namespaces](https://apptainer.org/docs/admin/main/user_namespace.html)). SIFs are read-only; writes need `--writable-tmpfs` (default 64 MiB, needs overlay/FUSE), `--bind`, or a `--writable` sandbox directory; directory overlays "generally do not work well" on Lustre/NFS, and setuid installs require root for bare-directory overlays [reported] ([persistent overlays](https://apptainer.org/docs/user/latest/persistent_overlays.html)). [inferred] The working pattern on LUMI is: per-trial copy of a user-owned sandbox directory (or a SIF plus a bound per-trial workspace directory on node-local `/tmp`), started with `apptainer instance start` and driven via `apptainer exec instance://…` (NeMo Gym pattern), with no fakeroot. Test whether `--writable-tmpfs` works on LUMI compute nodes; if it does, it is the faster RAM-overlay path the HPC fork describes as preferable [reported] ([harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc), [NeMo Gym Apptainer](https://docs.nvidia.com/nemo/gym/infrastructure/sandbox/apptainer/)). oellm-rlvr already uses "Apptainer overlays with read-only base images, bounded timeouts, and isolated workspace directories" on LUMI — reuse its overlay strategy [reported] ([oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr)).

**Caching and Lustre.** Keep SIFs (one file each) on Lustre and per-trial sandbox directories on node-local `$SLURM_TMPDIR`/`/tmp`; LUMI warns Lustre "simply isn't designed" for many small files and recommends containers or SquashFS-packed venvs, and says to point Apptainer cache dirs to `/tmp` to speed conversions [reported] ([LUMI Python docs](https://docs.lumi-supercomputer.eu/software/installing/python/), [LUMI Singularity docs](https://docs.lumi-supercomputer.eu/software/containers/singularity/)). Warm the node-local cache at job start (DeepSWE preloaded SWE-bench images on workers; K8s warm pools give "sub-second" claims vs image pulls) [reported] ([DeepSWE](https://www.together.ai/blog/deepswe), [agent-sandbox](https://agent-sandbox.sigs.k8s.io/docs/use-cases/examples/nemo-gym/)).

**Harbor Singularity flags and bugs to apply now.** `-e singularity --ek singularity_server_start_timeout=600`; raise `environment.build_timeout_sec` above conversion+staging time; apply PR #3146's PATH fix (or pin Harbor to a version containing it) because 46/88 TB-2.1-style images put Python only under `/usr/local`; raise the 600 s HTTP timeout for long verifiers [reported] ([PR #1722](https://github.com/harbor-framework/harbor/pull/1722), [#3126](https://github.com/harbor-framework/harbor/issues/3126), [harbor-singularity-hpc](https://github.com/lintangsutawika/harbor-singularity-hpc)). Run the oracle solution across all ~1,000 tasks under Apptainer before any RL and keep only tasks with oracle pass and no-op fail (the TB2.0 CI rule) [reported] ([TB paper](https://arxiv.org/pdf/2601.11868)).

**Flaky environments and tails.** Expect env.reset tails of "hundreds of seconds" and timeouts roughly once per ten iterations until tuned (RollArt); mitigate with redundant environment rollouts (launch surplus, kill slowest), partial rollouts (Kimi K2/K3, APRIL — integrated in slime with AMD support) and TB2.0's observation that most trials finish under 20 minutes with fewer than 25 model calls but some run 2 hours and hundreds of calls [reported] ([RollArt](https://arxiv.org/html/2512.22560v1), [APRIL](https://arxiv.org/abs/2509.18521), [TB paper](https://arxiv.org/pdf/2601.11868)). [inferred] With a 1,200 s agent timeout and 1,024 trials/step, plan for ~25–40 min per RL step of rollout wall-clock and mask timeouts rather than waiting.

### 5.8 ROCm / MI250X risk and the SkyRL FSDP path

Facts: SkyRL PR #2225 ("ROCm AMD: Megatron GRPO + vLLM inference servers on Instinct GPUs", MI300X/MI325X/MI355X, vLLM 0.20.2 ROCm builds, Slurm E2E launcher) was **closed unmerged on 2026-09-17** "will reopen when E2E GRPO is green"; reviewers flagged `torch.version.hip` detection, device-mask conflicts and wheel ABI caching; companion PR #2230 exists [reported] ([PR #2225](https://github.com/NovaSky-AI/SkyRL/pull/2225), [PR #2230](https://github.com/NovaSky-AI/SkyRL/pull/2230)). skyrl-train requires "CUDA version 12.8", Ray 2.57.0 and Python 3.12 [reported] ([skyrl-train README](https://github.com/NovaSky-AI/SkyRL/blob/main/skyrl-train/README.md)). verl's official AMD support lists only gfx942/gfx950 with a ROCm 7.14 image, "fully supports vLLM and SGLang", "FSDP, FSDP2 and Megatron", fully-async and colocate; caveats: disable vLLM custom all-reduce with `expandable_segments`, SGLang needs `attention_backend=triton`; MI250X is absent [reported] ([verl AMD](https://verl.readthedocs.io/en/latest/amd_tutorial/amd_quick_start.html)). AITER fails to build for gfx90a "due to inclusion of fp8 kernels" [reported] ([aiter #179](https://github.com/ROCm/aiter/issues/179)). Positive evidence on MI250X: LUMI AI Factory scaled verl + vLLM + Megatron GRPO (Qwen3-8B) from 1 to 16 LUMI-G nodes with weak-scaling efficiency 77.9–96.1%, but "TP4… failed during multi-node initialisation"; CSC's examples layer verl v0.8.0 in a venv on the LAIF container and form Ray with `ray symmetric-run` [reported] ([LUMI AIF](https://lumi-ai-factory.eu/articles/scaling-reinforcement-learning/), [CSC examples](https://github.com/CSCfi/llm-rl-fine-tuning-examples)); prime-rl ran Poro 2 RL "on the LUMI supercomputer with AMD Instinct MI250X" [reported] ([ROCm playbook](https://rocm.blogs.amd.com/artificial-intelligence/rl-training-playbook/README.html)); LUMI's PyTorch modules ship vLLM ≥0.6.3 inside AMD-built ROCm 6.2.4 SIFs, and require binding `/var/spool/slurmd,/opt/cray/,/usr/lib64/libcxi.so.1`, the aws-ofi-rccl plugin, `NCCL_SOCKET_IFNAME=hsn0,hsn1,hsn2,hsn3`, `NCCL_NET_GDR_LEVEL=3`, and MIOpen cache on `/tmp` [reported] ([LUMI PyTorch](https://lumi-supercomputer.github.io/LUMI-EasyBuild-docs/p/PyTorch/)); oellm-rlvr runs MI250X + ROCm 7 with vLLM compiled via Triton/Inductor, sequence parallelism disabled, and reports context-parallel GDN kernel compile failures and a 0.6 tok/s eager-mode smoke test for Qwen3.5-2B [reported] ([oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr)).

Recommendation [inferred]: (1) Run SkyRL FSDP on the LAIF/LUMI PyTorch+vLLM container and carry the PR #2225/#2230 patch set locally (HIP detection, `mp` executor on ROCm, weight-sync via RCCL); since SkyRL's inference backend accepts "any custom OpenAI API compatible endpoint that exposes a method to perform weight sync", run vLLM engines disaggregated on separate nodes rather than colocated, which sidesteps the colocated-executor issues flagged in the PR and matches the LUMI AIF finding that generation under-utilizes GPUs [reported basis] ([skyrl-train README](https://github.com/NovaSky-AI/SkyRL/blob/main/skyrl-train/README.md), [LUMI AIF](https://lumi-ai-factory.eu/articles/scaling-reinforcement-learning/)). (2) Keep TP ≤ 2 per node for vLLM on MI250X given the TP4 multi-node failure, and use DP across GCDs [reported basis] ([LUMI AIF](https://lumi-ai-factory.eu/articles/scaling-reinforcement-learning/)). (3) Use weight sync via checkpoint-and-load or gloo first, NCCL/RCCL once the Slingshot bindings are verified [reported options] ([skyrl-train README](https://github.com/NovaSky-AI/SkyRL/blob/main/skyrl-train/README.md)). (4) Keep verl 0.8.0 (proven on LUMI) or prime-rl as the fallback trainer with the same Harbor task set, since both have published AMD runs and prime-rl consumes Harbor tasksets natively [reported] ([CSC examples](https://github.com/CSCfi/llm-rl-fine-tuning-examples), [verifiers v1](https://www.primeintellect.ai/blog/verifiers-v1)). (5) Do not rely on FP8 or AITER paths on gfx90a [reported] ([aiter #179](https://github.com/ROCm/aiter/issues/179)). (6) Coordinate with OpenEuroLLM Taskboard #386, which is validating exactly this stack (SkyRL + Harbor + Terminus-2 + Apptainer on LUMI) and plans to evaluate NeMo Gym components [reported] ([#386](https://github.com/OpenEuroLLM/Taskboard/issues/386)).

### 5.9 Smoke-test ladder (Qwen3 1.7B–8B)

Step 1: `harbor run -d terminal-bench@2.0 -a oracle -e singularity` on one LUMI-C node to measure oracle pass rate and instance start time (the HPC fork's 37→42/88 oracle passes is the reference) [reported] ([#3126](https://github.com/harbor-framework/harbor/issues/3126)). Step 2: reproduce SkyRL's `run_codecontest.sh` with Qwen3-8B, 8 policy GCDs, group 8, batch 32, against the Apptainer backend via `--environment-import-path`; expected signal on OpenThoughts-TB-dev [reported basis] ([run_codecontest.sh](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train_integrations/harbor/run_codecontest.sh)). Step 3: Qwen3-8B on the 1,000-task mix for 100 steps; published 8B references: SETA 3.1→10.7 TB2.0 on one 8×H200 node, Endless Terminals 1.1→6.7, TMax Qwen3-8B 5.2 TB2.1, OT-Agent 8B SFT+RL 13.5 TB2.0 [reported] ([SETA](https://arxiv.org/html/2607.10891), [Endless](https://arxiv.org/abs/2601.16443), [TMax](https://arxiv.org/html/2606.23321v1), [OT-Agent](https://arxiv.org/pdf/2606.24855)). Step 4: the 30B run; targets by analogy are Tmax-27B 44.9 TB2.1 (RL-only from Qwen3.6-27B at 40.5) and Nemotron-Terminal-32B 27.4 TB2.0 (SFT-only from 3.4) [reported] ([TMax](https://arxiv.org/html/2606.23321v1), [NVIDIA](https://arxiv.org/abs/2602.21193)). [inferred] For a base-derived 30B with light SFT, a realistic first-run goal is 15–25% TB2.0 with Terminus-2; the TMax numbers assume a strong instruct starting point.

## 6. Gaps: what is not publicly known and what to test

- **No published agentic RL run on MI250X or any Apptainer-sandboxed fleet with throughput numbers.** oellm-rlvr is a control plane with open kernel issues; NVIDIA gives "hundreds of concurrent" Apptainer sandboxes but no seconds-per-start or trials/hour; Harbor-on-Apptainer has no throughput data anywhere [reported gaps] ([oellm-rlvr](https://github.com/BirgerMoell/oellm-rlvr), [Super](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf)). Test: instance start latency for SIF vs sandbox-dir on LUMI-C, with and without `--writable-tmpfs`, at 64/256/1,024 concurrent instances per allocation.
- **SkyRL on ROCm is unmerged and its AMD path is Megatron, not FSDP.** Whether SkyRL's FSDP backend + vLLM weight sync works on gfx90a is untested publicly [reported] ([PR #2225](https://github.com/NovaSky-AI/SkyRL/pull/2225)). Test: single-node GSM8K GRPO smoke on 8 GCDs, then 2-node disaggregated with NCCL vs gloo sync.
- **SkyRL+Harbor results are unpublished.** The Notion release post and docs.skyrl.ai were unreadable; no TB2.0 number for any SkyRL-Harbor-trained model exists in a primary source; the fully-async/step-wise combination (#1206) is open [reported] ([#866](https://github.com/NovaSky-AI/SkyRL/issues/866)).
- **RL from a true base model is untested.** All RL work starts from instruct/SFT checkpoints; TMax's no-SFT result is on Qwen 3.5 hybrids [reported] ([TMax](https://arxiv.org/html/2606.23321v1)). Test: base + 0 / 5K / 20K SFT traces, then identical RL, on the 8B smoke model.
- **No clean RL scaling curve in task count.** SETA's 560-of-4,567 subsample and TMax's dataset swaps are the only evidence; nobody reports "N tasks vs TB score" [inferred from notes]. Test: 250 / 500 / 1,000 tasks at fixed steps.
- **Group size and max-turn sweeps do not exist beyond TMax's 8 vs 32.** Test 8/16/32 at fixed trials per step (i.e., 128×8 vs 64×16 vs 32×32).
- **RLOO hyperparameters of OpenThoughts-Agent, the 1.7B/4B/14B OT-Agent scores, and the exact 100K/5K HF dataset ids are not in the fetched text** [reported gap] ([OT-Agent](https://arxiv.org/pdf/2606.24855)).
- **Nemotron Terminal-Task-Gen task directories (Dockerfiles + tests) are not released**; only trajectory parquet and the 630-task Pivot set [reported gap] ([HF corpus](https://huggingface.co/datasets/nvidia/Nemotron-Terminal-Corpus)).
- **Licenses unconfirmed** for OpenThoughts-Agent-v1-RL, Prime's Terminal-Lego/TMax registry copies, AdithyaSK datasets, TerminalTraj, TermiGen, SWE-Lego, Endless Terminals, SWE-Universe [reported gaps] (Section 4).
- **Decontamination against TB2.0 Dockerfiles/tests** (not just instruction n-grams) is reported by no dataset; contamination of terminal training sets against TB2.1/3.0/4.0 is unaddressed [reported gap] ([NVIDIA](https://arxiv.org/html/2602.21193v1)).
- **Closed labs: everything about training-time sandboxes, environment counts, algorithm and turns is not disclosed** (OpenAI, Anthropic, Google, xAI, Mistral); Anthropic's Fable 5.1 hack-rate figures come via a secondary source and need primary verification [reported] ([Fable 5.1 card](https://www-cdn.anthropic.com/0339e6a7c5c7b87f5c07798616dc32c215d14235/Claude%20Fable%205.1%20&%20Claude%20Mythos%205.1%20System%20Card.pdf)).
- **Network isolation under Apptainer** (no network namespace by default) and enforcement of task.toml `network_mode` on LUMI are undocumented [reported basis] ([Apptainer docker & OCI](https://apptainer.org/docs/user/latest/docker_and_oci.html)). Test with a canary task that must fail if outbound HTTP succeeds.
- **Nested-container tasks**: no primary source documents Apptainer-in-Apptainer without userns; assume impossible and filter [inferred].
- **Harbor's official Singularity docs page was not retrievable**; exact flag list and maintainers' HPC support stance are unknown [reported gap] ([sandbox docs](https://docs.harborframework.com/core-concepts/sandboxes/pre-integrated-sandboxes.md)).
